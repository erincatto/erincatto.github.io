Detailed Description

Save and restore the full simulation state of a world as a byte image.

Unlike a recording, which is a stream of API events, a snapshot is a single instant. Useful for rollback, undo, and deterministic save games. Call between world steps.

A snapshot carries only simulation state. Application hooks are not included. So callbacks and user data are not preserved. However, if you apply a snapshot to an existing world then the callbacks stay.

All the ids remain valid when a world is restored in place: b2BodyId, b2ShapeId, b2JointId, b2ChainId, and b2ContactId.

Write a snapshot of the world's simulation state into a caller-owned buffer.

Call once with image == NULL to get the required size, then again with a buffer of at least that size. Must be called at a step boundary.

Parameters
worldIdThe world to snapshot
imageDestination buffer, or NULL to query the size
capacitySize of image in bytes, ignored when querying
Returns
The number of bytes the snapshot needs. If it exceeds capacity nothing is written. Returns 0 if the world is mid-step.

Restore a world's simulation state from a snapshot image.

The b2WorldId and ids held from this same world stay valid for objects that existed at the snapshot instant. Callbacks and threading configuration are preserved. User data on shapes, bodies, and joints is nulled.

Parameters
worldIdThe world to restore into
imageA snapshot image produced by b2World_GetSnapshot
sizeSize of image in bytes
Returns
true on success. On a rejected image (bad magic, version, or layout) the world is left unchanged. A corrupt payload detected after the rebuild begins returns false and leaves the world unusable, so the caller must destroy it.
